# ADR 0010: Writable memory isolation with explicit maintenance composition

Date: 2026-10-06. Status: implemented internal milestones 7b4, 7b5 and 7b6; package remains 0.2.0 and all selected work still ships together in v1.0.

## Decision

Move the actual SQLite MemoryService operations into `src/adapters/memory/sqlite-store.ts` behind the existing MemoryStore port. No eighth port is introduced. The internal SqliteSession is a synchronous native callback lifecycle, not a domain port. Its plain transaction/helpers move to `sqlite-session.ts` and retain exact legacy exports; registered sessions retain existing admission, native handle privacy, same-inode HOLD and old writer fencing.

The adapter owns store/update/archive/proposal/purge behavior and forwards SELECT/projection/FTS to `sqlite-query.ts`. `sqlite-maintenance.ts` owns explicit expire/touch/prune mutations and audit inserts. Read helpers never call maintenance or index code. The existing FTS triggers still index explicit content writes. Exact schemas, validation behavior and cleanTags move to `src/contracts/{schema,memory}.ts`; all existing legacy callers retain forwarding identity. Selected external schema/TOML/HTTP libraries remain step 3 dependency gates; this extraction neither installs them nor substitutes a fake implementation.

Composition supplies a session, semantic clock, monotonic clock, retention policy, ID/hash functions and measurement sink. Callback values and retention settings are copied; retention is frozen. The legacy binding preserves ID shape and normalized SHA-256 hash values. Semantic timestamps and computed expiry are safe integers in the Date-ms range 0–8,640,000,000,000,000, checked before DML. Delete/purge use one captured operation timestamp. Measurements contain only an allowlisted operation, finite non-negative ms/count/character numbers and success flag; they contain no title/body/tags/IDs/hashes/errors. Timing/size/sink failures are best effort and cannot turn a successful source commit into a failed reply or replace a business/dependency error.

## Direct reads and compatibility

The direct adapter constructor performs no expiry. Direct search filters unarchived expiry using its injected clock and accepts finite expiry only when stored as an integer Date timestamp. Text/blob/fractional/out-of-range expiry cannot compare as an eligible future value, and denied rows are filtered before payload/tag projection. Archived searches remain owner inspection. The old `touch` query flag remains accepted by the port but causes no direct search writes; access recording is an explicit maintenance operation.

Direct get deliberately inspects the persisted owner row and its actual events. It does not hide an expired active row, manufacture an archive DTO/version/event, or prove model delivery eligibility. Calling explicit expire later archives the row, increments its version and adds the existing retention event. Model delivery/finite-expiry handoff needs its own policy and lease qualification; the existing hook/public readers remain unchanged and gain no writable dependency.

`lib/memory/service.ts` binds the legacy config, clocks, ID/hash functions and metrics sink and extends the actual adapter with explicit compatibility maintenance. Existing callers still expire on construction and before get/search, see an expired row as archived with its actual event/version, and best-effort touch successful FTS matches. Whitespace-only listing does not touch. Public schemas, IDs, dedupe, versions, scopes, raw malformed legacy privacy/sharing flag handling, owner business errors, private owner inspection and transaction-time MCP projection remain compatible. The public cfg property remains available; configured retention is selected when opening and requires reopening to change.

The existing local/remote selection and authoritative local serve composition are unchanged. Default legacy open/migration/config/logging behavior remains in lib. Query SQL isolation is an effect claim for established sessions: native WAL/SHM housekeeping on arbitrary SQLite opens, telemetry/config effects in legacy caller closures and model delivery are separate boundaries. This milestone does not make the whole CLI/MCP/context path zero-IO or replace the qualified hook reader.

## Owner sharing and expired session restore (7b6)

Owner add/update accept `--shared|--unshared`, mapping to the existing shared boolean. Their combination fails immediately after argument parsing, before project discovery, file input, providers or storage opens. Update forwards the existing `--status active|archived` option to Patch.status, including status-only updates; proposed/unknown states retain shared PATCH validation refusal. No new verb, schema, domain port, MCP field or broad retention API is added. Unsharing removes cross-project access while preserving owner and explicitly linked reads; it changes no omitted raw privacy flag.

An admitted update reads the exact writable row and expected version, checks duplicates and then captures one injected operation timestamp. Only an explicit archived-to-active session transition with a valid deadline at or before that timestamp renews expiry. Renewal uses the current frozen sessionTtlDays policy, sharing creation's Date-ms/overflow validation before DML; zero disables expiry. The unchanged schema retains an absolute deadline, not the selected duration, so a prior custom TTL cannot be inferred. Future/null deadlines, ordinary edits, proposals and non-session TTL semantics remain unchanged. Malformed stored session expiry refuses explicit restore with a finite unavailable error; ordinary omitted expiry and private/shared fields remain preserved. The row/version increment and restore event commit atomically using the same time, ID/hash and established provenance semantics.

Legacy construction/get maintenance can first archive an expired active row and advance its version. The CLI's default version lookup uses that resulting persisted version; an explicitly stale version still conflicts. MCP status-active restoration remains compatible for private and malformed-private records and returns only the existing opaque receipt. Existing source admission, HOLD/public revocation and cached-writer fences still govern these mutations. No model-delivery lease or general expiry handoff guarantee follows.

Guarded native plain/registered fixtures exercise renewal from a historical custom TTL, reopen/get/search and expiry at the new boundary, one operation clock/event, zero policy, raw flags, audit/version/hash/ID parity, deadline preservation and clock/overflow/conflict/malformed-expiry failures before source DML. Actual owner CLI fixtures cover sharing choices/help, pre-effect conflict rejection, status-only restore with post-maintenance versions, invalid status refusal and reopen. Actual stdio MCP fixtures restore and unshare public/private/malformed-private session rows, preserve opaque replies and reject cross-project/stale-version access.

## Qualification

The guarded `memoryadapter` suite runs real native plain and registered SQLite fixtures through direct MemoryStore and legacy composition. It covers mutation/dedupe/hash/ID/schema/version/scope/privacy/proposals/audit parity, unchanged file/table/event/generation footprints for established-session queries, malformed expiry/private/shared filtering before projection, deterministic expiry/touch/prune and frozen retention. A retained native public-view lease permits direct queries while holding mutation; release permits registered mutation. Cached writers remain fenced across public format upgrade and fresh writers revoke READY to HOLD.

Actual rows/events/generation and returned receipts survive post-commit throwing measurement sinks and broken timing sources. Invalid clocks/expiry overflow/dependency failures leave rows/events unchanged; rollback and constructor/close error preservation are exercised. A guarded child imports only the direct adapter/session and operates in-memory with invalid ambient config and settings, leaving its synthetic owner directory unchanged. Validator/schema/session legacy exports retain exact identity. Boundary negatives reject adapter-to-lib access, ambient config/clocks/timing, runtime external imports in the exact six extracted files, contract-to-storage access, query-to-maintenance imports, hook-to-writer imports and unrelated service forwarding. Root also reproduced and closed unreviewed internal contract-helper, static reexport and tsconfig-alias paths to ambient state. Isolated runtime imports are limited to checked core or the exact reviewed isolation set; erased type dependencies remain permitted. Type-only node:sqlite stays permitted; effectful native lifecycle adapters are outside that narrow isolation set.

Independent coordinator final full verification passed 365 application tests plus 18 containment groups, strict typecheck and boundaries (63 files / 222 edges / zero violations). Final boundary fixtures passed 53/53 plus 18 containment; focused worker application checks passed 183/183 plus 18 containment before the final guard tightening. Detailed actual checkpoints are recorded in [the implementation ledger](../plans/2026-10-04-bosun-v1.0-implementation-ledger.md).

These are synthetic trusted-application fixtures. They make no hostile-sameUID, live-host/service, designated-Mac performance, power-loss durability or retained MCP transport lease claim.

## Docs query/index isolation (7b5)

`sqlite-docs.ts` implements the actual docs ContextSource and compatible MemoryProvider against a supplied synchronous SqliteSession. Constructor/search perform no discovery, Git, filesystem indexing, telemetry or clock effects. Frozen configured root/project/excluded-root scope controls SELECT before title/snippet projection; trusted ctx must authorize that project directly or through its explicit linked-project list. Model tool arguments cannot select projects. Relative path IDs, persisted seq/path keys, title/snippet/BM25/mtime, schema/FTS and owner project semantics remain compatible. Registered session effects/admission remain their existing separate boundary.

`sqlite-docs-index.ts` is a separate explicit index operation receiving workspace enumeration, regular-file inspection/revalidation, callback-local storage checks, monotonic clock and content-free measurement dependencies. `docs-filesystem.ts` owns native effects without importing lib. Enumeration must succeed, be complete/NUL-terminated, decode valid UTF-8 and stay within 2 MiB/2000 Markdown files. Failed Git commands, partial output, listing/count/aggregate overflow and transient source errors hold the whole attempt before deletion, never truncate and pretend the tail is absent. Bound total stored docs to 10,000 rows/16 MiB encoded; new strings use conservative UTF-8 upper bounds before staging.

Resolve the actual canonical root and reject symlink/dangling/directory/multi-link/oversized sources before reading bytes. Descriptor reads cap at 256 KiB, use no-follow/nonblocking opens and verify root/ancestor/path/descriptor stamps before/after reading and before/after admitted DML. Stable missing/ignored/rejected owned records are removed; unexpected source changes or partial reads hold/rollback. Native helper .git checks use only presence/metadata. Distinct absolute worktree keys and foreign projects remain untouched. Same-project nested descendant ownership cannot be reconstructed from the unchanged schema: preserve those ambiguous rows and exclude the nested root from the outer query, rather than guessing deletion/adoption. Prior exclusions remain conservative.

Native storage checks keep source-plus-WAL 64 MiB eligibility, reserve eight times the new encoded upper bound plus 12 KiB per changed/deleted row before DML, and recheck actual physical size afterward. The estimate qualifies the tested corpora, not an arbitrary SQLite final-COMMIT/FTS allocation ceiling. Existing registered confirmed/paths checks enforce size before callbacks; floor UDFs enforce canonical identity/admission/HOLD, not a full 64 MiB size check on every row. Central final-COMMIT capacity/recovery qualification remains a separate v1.0 storage gate. No authorizer widening, permission change, storage-file adoption/deletion or schema migration occurs.

`lib/memory/docs.ts` remains composition/forwarding with default search-triggered indexing until daemon callers and scheduling migrate. These legacy MCP/context reads still write; a held attempt returns no compatible docs and preserves the saved index. Replace the immutable query scope only after a newly validated successful index result. Direct queries read a persisted snapshot: they do not prove live filesystem revocation or discover newly nested repositories, and require a freshly validated excluded-root scope for those changes. There is no retained MCP/model-delivery lease claim.

Native pre-fix fixtures failed four actual assertions: successful Git root lookup followed by failed ls-files deleted known rows; a 2001-file listing inserted 2000/deleted the unvisited valid tail; outside symlink body/title reached search; parent prefix deletion evicted another project. The guarded docs suite adds actual plain/registered ContextSource acceptance, query file/table/generation/metrics footprints, seq/FTS/rank projection, 2000/2001 boundaries, malformed/overflow listings, short descriptor reads, read/pre-DML/post-preflight source races, deletion/rejection/ignore, real Git worktrees and nested repositories, private outside/project canaries, registered READY lease/HOLD and writer fencing, storage hold/rollback, post-commit throwing telemetry and a direct-only ambient-free child import. Actual CLI stdio MCP/context calls validate trusted projects and fail closed on held indexing. The launcher exposes `docsadapter`, included in `all` and `contracts`; boundary negatives reject query-to-index/helper, ambient source/timing, platform/contract alias and unrelated legacy forwarding escapes. Coordinator verification is recorded separately in the ledger.

## Dependent work

Daemon migration must select direct memory/docs query APIs, schedule expiry/prune/indexing explicitly, and enqueue admitted access updates when appropriate. Legacy maintenance/index composition remains until those caller/scheduling changes preserve behavior; it cannot be removed by calling existing writable reads read-only. Hook snapshot/lean closure, CLI unsharing/expired restore semantics, central final-COMMIT capacity/recovery, storage/artifact disposition and drain remain required in roadmap step 2 and its dependent steps. All native-host/Clef/daemon/handoff/graph/dashboard/remote and one-v1.0 ship gates remain required. Root portable context and the implementation ledger track completion separately.

Coordinator review also reproduced/fixed preserved-timestamp edits on plain/registered sessions and descriptor cleanup failures. Native listed bodies are bounded/read/validated even with equal timestamps, then unchanged content/title/mtime avoids UPSERT and generation/HOLD changes. Cleanup failure holds indexing and attempts one identity-bound retry without promising release. [ADR 0011](0011-scoped-docs-query-and-index.md) records the complete docs decision.
