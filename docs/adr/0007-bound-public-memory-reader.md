# 0007 · Bound public memory reader and local handoff

**Status:** Implemented for explicitly bound READY views and non-expiring local notes; strict owner workflow in ADR 0008, broader activation/recovery and finite-expiry handoff held. **Date:** 2026-10-06.

## Decision

The local hook uses `openHookMemory` through its existing literal `lib/route.ts → sqlite-readonly.ts` compatibility seam. A present/pending view, explicit view override or source binding selects the public reader and never falls back to primary rows on failure. An absent default view with blank binding retains the qualified unactivated rollback reader and its default-WAL hold. A floor-bearing rollback primary is also rejected by the legacy reader. Selection creates no files, directories, permissions, floor or publication; missing/corrupt/uninitialized/old-format/HOLD/stale/mismatched views stay unavailable. Remote memory behavior remains compatible.

`MEMORY_SOURCE_ID` is an independent explicit owner binding to the random `sourceId` saved in the initial owner plan/cutover receipt. It is blank by default. The reader requires a valid matching UUID; it never learns its expected source epoch from the candidate view and never writes owner configuration. [ADR 0008](0008-strict-owner-memory-cutover.md) implements explicit apply/reconciliation for strict prepared layouts. Permission adaptation and verified drain/restart remain held. Existing plain installs retain the WAL hold until an owner explicitly prepares, applies, publishes and independently binds a READY view.

`SqlitePublicReadOnly` opens only the fixed rollback view through SQLite, with native read-only/defensive/no-extension options and connection-only query-only, memory-temp, zero-busy-wait and EXCLUSIVE-mode settings. It starts one read transaction during acquisition and retains that native lease through scoped queries, packing and native stdout acceptance. `close` releases it. Actual registered revocation must commit HOLD on this same inode before primary DML, so a retained lease prevents a supported writer from advancing source data/generation. Generation is pinned to READY within that lease; no mutable-primary SQL generation query is performed.

## Binding and projection

Preflight validates canonical ordinary paths, exact owner-only 0700 parent directories/0600 single-link files including special mode bits, distinct source/view device+inode identities, rollback view header, 64 MiB view cap and lstat absence of view journal/WAL/SHM, including dangling links. A minimal filesystem-only source check reads its first 20 bytes and requires WAL header mode and absence of a source rollback journal. Source plus WAL remains bounded at 64 MiB. A present WAL requires canonical owner-only single-link regular metadata, distinct identity and only its empty/minimal 32-byte header; the first observed WAL inode stays pinned across lease checks. Absence/empty native housekeeping is allowed, while replacement/alias/dangling/bad mode/header/aggregate size holds. It never opens mutable WAL through SQLite, hashes frames/bodies, reads the owner backup, recovers a journal, creates temp files, changes modes or checkpoints/copies a primary. A raced WAL view is held by the same measured exclusive-mode native backstop as the legacy reader.

Exact public/recovery/FTS/shadow/maintenance schemas come from the IO-free `sqlite-public-protocol.ts` literal module shared with the explicit publisher. Reader imports exclude cutover/writer/config/log/metrics/model code. Only projected recovery gate protocol/phase/epoch/device+inode fields are selected; owner backup name/digest/recovery derivatives are never selected into JavaScript or output. READY format, independent source epoch, safe generation, random publication UUID, publication time and earliest-expiry validity are checked inside the lease and pinned. Identity/header/sidecar/state/clock checks run around each query and immediately before hook queuing. A clock moving backward or expired earliest-expiry READY state holds without refresh.

Whole-view row-count/encoded-size/earliest-expiry checks return SQL scalars, bounded at 10,000 rows and 16 MiB encoded; constructor checks do not materialize foreign project bodies. These IO-free shared constants match publication; strict owner storage/header checks retain their 64 MiB data-file ceiling. The encoded SQL JSON aggregate is qualified against publisher JSON for multibyte, quotes, backslashes and control characters. Search/get apply public integer-zero classification, active status, query-time expiry and personal/own/shared/linked scope in parameterized SQL before content decoding. Scoped DTO validation preserves all current public IDs/hash/version/provenance/access/packing fields, validates current content hash, and keeps FTS BM25/distinct-match behavior. Denied get returns finite not-found; events, private/touch requests and malformed/bounded query inputs are rejected. Dependency getters/proxies cannot emit their error text or extra fields.

## Delivery-time expiry

A retained database lease blocks revocation, but does not stop the clock. Native pipe/socket writes can accept buffered data after a finite expiry under real backpressure or a stalled event loop. Pre-write checks, timer slack, or a callback-time check cannot retract already accepted bytes and do not prove finite-expiry delivery safety.

The concrete local hook therefore sets `nonExpiringOnly:true` on **both public-view and legacy rollback readers**. `expires_at IS NULL` is enforced in SQL before projection and packing. Ordinary reader APIs retain query-time finite-expiry semantics; earliest-expiry metadata can hold an entire stale publication and requires explicit republish. Local finite-expiry notes, including session TTL notes, remain omitted until a separately qualified handoff strategy exists. Useful non-expiring notes retain the existing lease through native stdout callback. Real backpressure and a 1,250 ms event-loop stall exercise this omission on both paths.

Existing delivery qualification remains Node POSIX pipe/socket, a 16 KiB serialized memory envelope and a 250 ms event-loop pending timer. Pending write error/signal/timeout terminates the one-shot producer with its lease retained to OS teardown; SIGKILL releases only by teardown. No host acknowledgement, total latency, native SQL interruption, hard timer deadline or p95 claim follows. File/TTY/Windows/Bun sinks omit local notes before DB open. The whole hook still runs legacy routing, context and telemetry work outside the zero-write reader; lean closure/daemon support is unfinished.

## Verification and limits

The guarded `publicreader` suite uses production explicit cutover/publication on synthetic roots, actual local registered writers and child hook stdout. It covers scoped search/get/query bounds, independent missing/wrong binding, exact schemas/state/epoch/generation/publication/time/data, hashes and multibyte encoding, aliases/modes/size/inodes/source-header/offline-rollback-restore rejection, private/audit/backup canaries, before/during/after reader footprint, retained revocation, native callback/cancellation/SIGKILL/backpressure/stall and an actual killed hot spill journal. `hooklease` adds a targeted native rollback finite-expiry regression; existing publication/readonly tests remain required. Run through the mandatory Node launcher, isolated typecheck, AST boundaries and whitespace checks. No Bun tests, installs, private owner data, personal config writes, version bump or commit occur.

The expected epoch and inode binding do not detect an arbitrary same-inode WAL-primary restoration/independent epoch change that leaves the old view and old owner binding in place. The header check rejects obvious corrupt/truncated/offline rollback restores only. Explicit restore/epoch rotation and verified revoke/drain/restart remain gates; they must not silently preserve old audience eligibility. [ADR 0008](0008-strict-owner-memory-cutover.md) implements strict owner preparation/apply and bounded incomplete recovery, without general restore. Deliberate same-user schema/UDF/filesystem tampering remains outside the trusted-application protocol. Process-kill evidence is not power-loss or broader platform qualification. The former 4 MiB 10k hold is historical: [ADR 0006's capacity follow-up](0006-explicit-public-memory-publication.md#useful-bounded-capacity--7b2d) now proves useful scoped/native delivery from that medium-body corpus within 16 MiB encoded/64 MiB physical limits. Durability, performance, finite-expiry handoff and daemon freshness scheduling remain same-v1 shipment gates.
