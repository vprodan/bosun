# 0006 · Explicit public memory publication

**Status:** Implemented publication and registered revocation; bound reader in ADR 0007 and strict owner plan/apply/reconcile in ADR 0008. Broader activation/recovery held. **Date:** 2026-10-06.

## Decision

`bosun memory publish [--json]` calls `publishLocalMemory → publishMemoryView` directly for an already-applied local floor. It rejects remote, plain/missing stores, extra positionals and all other flags. It never invokes the legacy opener, creates a primary/view/backup/directory, adapts permissions or installs the initial floor. Existing `bin`/config loading can still initialize configuration as before; the publication operation itself creates no missing storage. The separate strict owner cutover workflow is implemented in [ADR 0008](0008-strict-owner-memory-cutover.md).

The existing owner-only recovery gate stays unchanged and always HOLD. The same fixed rollback inode gains exact `bosun_public_state`, `public_memories`, external-content FTS and maintenance-trigger schemas. No view file replacement, primary mode conversion/checkpoint, immutable primary or live filesystem copy is used. Public state has format, source epoch, generation, random publication UUID, publication time and earliest published expiry; owner backup paths/digests remain only in the original recovery metadata. Receipts contain only READY plus the random publication UUID.

## Format upgrade and admission

An explicit publisher acquires actual primary `BEGIN IMMEDIATE` and validates the source schema, existing applied floor, fixed source/view identities and immutable owner backup digest. It commits the public schema and HOLD state on the fixed view inode, then installs a persistent v2 source marker and all nine triggers requiring `bosun_writer_floor_v2` in one primary transaction. Write admission is retained through this format commit. Generation, original cutover epoch/attempt/backup, owner rows/events/docs/IDs/scope/versions and source FTS remain unchanged.

A crash after the view upgrade but before primary commit leaves view-v2/source-v1 HOLD. Ordinary local opens refuse that mismatch; only this explicit publisher may finish the matching empty-HOLD upgrade. A primary-v2 marker is never silently downgraded or reinstalled. Each registered connection binds its construction format: cached v1 MemoryService/Docs and old prepared/plain writers fail after upgrade, even when running the new source code. Reopen the authorities explicitly. New v2 connections independently FULL-commit public HOLD before any memories/events/docs mutation. Primary rollback does not undo revocation; successful mutation stays held until another explicit publish. No automatic freshness scheduler/rebuild is introduced.

The publisher takes primary admission for the build, commits HOLD independently **before** selecting/rebuilding, and commits public rows+FTS+publication metadata+READY atomically in a view transaction while admission remains held. A view lease can prevent HOLD/schema commit and thus prevent source mutation/publication. An admission/lease failure that never commits revocation leaves the previously valid publication intact. Failed builds after durable HOLD stay held. Explicit `cutoverMemory` reconciliation of a v2 view also revokes public READY before returning its original floor-1 HOLD receipt; it never implies revocation that did not commit.

## Public projection and bounds

SQL selects only integer-private-zero, active, nonexpired records before content projection. Private/unknown flags, proposals, archived/expired rows, audit/events and docs are excluded. Each eligible record validates established nonempty ID bounds (not a new ID generator), category/project consistency, optional session/provenance, tags, booleans and safe integer/version/timestamps. Its stored hash must match the normalized current public title/body hash. The fixed projection preserves all current public Memory fields, including IDs/scope/session/source/sourceRef, hash, access/version/timestamps and packing fields. [ADR 0007](0007-bound-public-memory-reader.md) implements compatible scoped search/get mapping without fabricated provenance. Classification is explicit, not automatic secret detection.

Primary+WAL cap remains 64 MiB. Publication and reader now share 10,000 selected records, 16 MiB of encoded public rows and a 64 MiB physical view. Record/query/output limits stay unchanged. The guarded medium-body 10k corpus now publishes READY and supplies useful scoped/native hook notes, as recorded below. **Historical checkpoint:** the former 4 MiB encoded/16 MiB physical limits held that corpus before READY. That failure exposed a capacity gate; a row ceiling alone had not qualified useful retrieval. The new functional result does not establish every 10k corpus, the historical benchmark's performance or a retrieval latency/p95/token guarantee. Clock/UUID values must be synchronous and valid; time, earliest expiry, identities, epoch/backup and generation are rechecked after fallible checkpoints and before READY. The owner checkpoint may await under admission and prolong it; synchronous SQLite work has no hard interruption deadline.

## Recovery and uncertain receipts

Small killed builds leave non-hot journals when dirty pages stay cached. A separate spill fixture demonstrated a synced nonzero hot-journal header and changed view pages before SIGKILL. Ordinary local callers hold pending journals without view changes. Explicit publisher recovery first holds primary admission and validates exact source floor/format/epoch, immutable backup digest, canonical owner-only 0600/nlink1 fixed view and bounded journal; symlink/hardlink/mode/WAL/inode/authority mismatches are rejected. Sidecar presence uses lstat so dangling links cannot appear absent or create an unrelated journal target. Only then may native SQLite recover this owned rollback journal. Restored gate/schema/epoch must validate and HOLD is committed before rebuilding. Cleanup revocation refuses pending sidecars instead of attempting recovery. No journal is guessed, deleted or filesystem-replayed by bosun.

All fallible owner callbacks, including `ready`, are **before READY commit**. Post-commit native confirmation/commit/close errors still exist. The operation attempts to re-HOLD only its validated same inode/epoch. If a real read lease or storage/identity failure prevents re-HOLD, it returns finite `receipt_unknown` with `outcome: unknown`; the owner CLI says the local publication outcome is unknown and requires another explicit publish. A valid committed READY may remain under that lease, with no success receipt. A failed receipt therefore does not universally prove HOLD. Unknown/replaced artifacts are never repaired to manufacture a receipt.

HOLD revokes audience eligibility; it does not erase cached JavaScript, previously-public rows, old pages or the owner recovery metadata. Rebuild removes rows from the logical public projection, without a physical erasure guarantee. At the original publication checkpoint, the future reader still needed to validate public state/identity/generation, filter scope/expiry and retain the same-inode lease through handoff. Earliest-expiry metadata and pre-commit checks did not qualify delivery crossing an expiry boundary. Default-WAL hook notes were held with no READY reader, daemon/remote view, owner floor activation or delivery-time expiry protocol activated. The bound-reader follow-up below implements the explicitly bound non-expiring path; ordinary unactivated WAL and finite-expiry handoff remain held.

## Verification and remaining gates

The guarded `publication` suite uses the production cutover, explicit publisher, real MemoryService/Docs and CLI, old prepared writers, native leases, concurrent real CLI contenders, six pre-commit SIGKILL boundaries and a separate child killed after successful publication. It checks owner/backup parity, fixed inode/reader footprint, partial-format restart, hot-journal recovery, private/audit/backup canaries, unknown schemas/paths, clocks/expiry, 10k capacity and post-commit uncertainty. Use the mandatory Node launcher, isolated typecheck, AST boundary checker and whitespace checks. No production-to-test dependency or new port is added; the existing ADR 0001 compatibility edge now includes explicit publisher composition.

This remains a trusted-application protocol; same-user deliberate schema/UDF/authorizer/file manipulation can bypass it. Process-crash evidence is not power-loss or cross-platform/native-host/Bun qualification. Strict owner preparation/apply and bound non-expiring reading are implemented in ADRs 0007/0008; verified draining/restart, expiry at delivery, restore/orphan disposition, performance and broader durability/storage failure remain same-v1 shipment gates.

## Bound reader follow-up

[ADR 0007](0007-bound-public-memory-reader.md) implements exact public-view reader binding with an independent expected owner epoch, retained same-inode lease and scoped projection. It omits finite-expiry notes from both local hook paths before packing, since buffering/backpressure/stalls defeat timer-based expiry guarantees. Ordinary installs remain held without explicit owner activation and binding; finite-expiry handoff, general restore/recovery and performance remain same-v1 gates. The future-reader statements above describe the earlier publication checkpoint, not proof of those later gates.

## Useful bounded capacity · 7b2d

The same medium-body corpus retains 10,000 public rows plus three denied private/unclassified/proposed source canaries, with actual project scope. One guarded Node 24.16.0 / SQLite 3.53.0 run measured:

| Quantity | Observed bytes | Finite ceiling |
|---|---:|---:|
| Encoded public projection | 9,325,226 | 16,777,216 (16 MiB) |
| Physical rollback view, including FTS | 7,864,320 | 67,108,864 (64 MiB) |
| Primary plus WAL | 14,458,744 | 67,108,864 (64 MiB) |

The fixed schema/format, source epoch and 10k row ceiling are unchanged. Bounds leave room for this demonstrated corpus and SQLite/FTS overhead; they are independent, so larger valid multibyte bodies still exceed the encoded limit below 10k rows. The publisher checks physical page count before READY; oversized existing source/view preflight fails without modifying unknown/unqualified artifacts. An existing READY marker may remain physically unchanged in that case, but the independent reader refuses audience eligibility. A publisher error does not universally prove a durable HOLD.

The reusable capacity fixture proves actual READY with expected scoped get/search IDs/body/hash/provenance and BM25 matches, denied-scope/private omission, source/view/backup byte parity across native reading, wrong-binding no-memory, and one useful native pipe/socket hook injection with output/metric parity. Its retained public reader blocks actual registered privatization before source DML; close allows the mutation and committed HOLD. Finite-expiry notes stay omitted. Negative fixtures isolate row count, encoded multibyte aggregate, 4,001-character body and oversized source/view limits without partial READY. Reader negatives independently enforce logical limits within the physical cap, full permission bits and source-WAL metadata/minimal-header/aggregate/inode limits, without recovery or content projection.

The explicit synthetic `memory bench --n 10000 --public-view` uses existing legacy SQLite owner wrappers, prepares/applies/publishes only its closed generated temp corpus, saves the independently planned epoch and binds real child hooks. Owner storage/source epoch/remote/claude-mem choices are cleared; owner canary bytes and owner metrics remain untouched. The seed-42 10k fixture proves 20/20 native injections with matching child metrics. Default bench still measures the unactivated-WAL hold; failed/held/unqualified arms never produce retrieval timings. This adds one legacy bench-to-SQLite edge, with no adapter seam/core port change or model/service start. CLI configuration initialization and content-free migration logging remain as before.

These are functional synthetic capacity observations, not designated-Mac p95, hard deadline, live-host, Bun/cross-platform, power-loss or arbitrary same-user isolation qualifications. Verified drain/restart, restore/epoch rotation, durability, finite-expiry handoff, daemon refresh, Clef/native-host integration and automatic handoff remain required.
