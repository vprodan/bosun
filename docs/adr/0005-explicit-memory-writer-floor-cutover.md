# 0005 · Explicit memory backup and writer-floor cutover

**Status:** Implemented explicit primitive, registered callers and explicit publication; owner cutover activation/hook reader held. **Date:** 2026-10-05.

## Decision

`src/adapters/memory/sqlite-cutover.ts` implements `cutoverMemory` and `CutoverWriter`. The latter now serves real local MemoryService/owner CLI, MCP memory/docs and authoritative server lifecycles when an already-applied explicit floor is present. `cutoverMemory` is never invoked by the default opener, hook, CLI, MCP or server: no floor is installed automatically and no apply/recovery CLI command is added. Default-WAL hook notes remain omitted and safe useful WAL fallback still blocks the same v1.0 shipment.

This closes the backup-to-floor admission gap identified in [ADR 0004](0004-wal-read-view-protocol-qualification.md). The explicit operation acquires actual primary `BEGIN IMMEDIATE`, holds it while native SQLite backup reads committed WAL state through a separate source connection, and retains it through the transactional floor schema commit. A contender cannot mutate between the exact backup and admission floor. The source stays WAL; IDs, all memory rows (including private/proposed/expired data), audit history, docs, indexes and existing FTS-maintenance triggers are preserved.

The caller supplies canonical primary/view paths, a separate existing backup directory, a clock and UUID factory. Directories must be owner-only 0700 and files owner-only 0600, without symlinks/hard links or aliases. Source plus WAL size is capped at 64 MiB and rechecked under admission. Current migration-1 schema is pinned by a normalized `sqlite_master` fingerprint, including FTS shadow tables. Extra/changed schemas and unsupported native prerequisites fail with finite `CutoverError` reasons, without returning storage/provider messages, paths or content. Paths are ordinary native paths, never SQLite URIs; ATTACH/extensions are not used.

Legacy `openDb` creates directories with the process's default mode, so an existing v0.2 `.bosun` directory can be 0755 even though its database is 0600. The primitive deliberately rejects that layout and never chmods it. Subsequent owner activation must explicitly check and plan any permission adaptation; these strict checks are not evidence that every existing installation is immediately compatible.

The concrete local composition is `openLocalSqlite`: it checks presence/schema before the legacy `openDb` can chmod or migrate. The default gate is `<primary-dir>/memory-view/public.db`, with backups in `<primary-dir>/memory-backups`; `MEMORY_VIEW_PATH` and `MEMORY_BACKUP_DIR` can override them through normal environment/config loading. A floor marker, pending gate, explicit path selection or ambiguous/dangling gate cannot fall back to a plain opener. A valid applied floor selects `CutoverWriter`; ordinary unactivated stores retain legacy creation/migration behavior. Registered selection creates no directories, adapts no permissions, installs no floor and automatically repairs nothing. This writer-discovery probe may open mutable WAL and perform native sidecar housekeeping; it is not the zero-write hook reader.

## Gate and interruption state

The fixed rollback **view inode itself** initially contains the `bosun_cutover_gate` recovery row, always `HOLD`. Explicit publication now upgrades this same inode with a separate exact public-state/rows/FTS schema and persistent v2 writer-format marker, per [ADR 0006](0006-explicit-public-memory-publication.md). The owner recovery row stays unchanged/HOLD; public state can become READY only through `memory publish`. Future readers must retain this file's gate/read lease through handoff; locking a different public-rows file would not protect revocation. No hook reader is activated.

Clock, UUID and callback inputs are checked before file reservation. Initial gate schema and its first valid row commit atomically. A crash before that first durable intent can leave a reserved empty/uninitialized file or orphan artifact: it stays unavailable and is never automatically adopted or overwritten. Recovery of such unknown pre-intent files requires separate explicit owner disposition; this primitive does not guess ownership from an empty file.

The durable gate records the random source epoch, attempt UUID, source/view device+inode identities, backup basename+identity+digest and owner timestamp. The primary floor row binds the same fields and a safe integer generation. These are **owner-only recovery metadata**, not telemetry or model replies; the receipt contains only `HOLD`, floor, random source/attempt IDs and observed generation. No new logging is performed. The backup digest covers private data and must never become a model-facing field or identifier.

Each attempt reserves a fresh UUID-named artifact with `wx`/0600. The native backup initially inherits WAL header format. Only the completed owner backup is finalized through SQLite `journal_mode=DELETE`, checked for integrity/current schema, closed, checked for rollback header and absence of sidecars, digested and fsynced. This converts the offline destination only; it never filesystem-copies a live primary/WAL pair, switches primary mode or issues a primary checkpoint. Native connection close may perform ordinary writer housekeeping; this is an explicit writer operation, not a zero-write reader.

The gate advances `copying → backed → applied`, with the source floor and all nine triggers installed in one primary transaction. No `applied` receipt is returned before post-commit source/view/backup identity, digest and gate/floor reconciliation. A committed-but-unrecorded floor is reconciled without reinstalling triggers or resetting generation. If the primary transaction rolled back, ordinary legacy writers could have changed it: recovery takes **another fresh exact backup under fresh admission**, never silently reuses the old backup. Old artifacts remain byte-for-byte preserved. Unknown/missing/corrupt metadata, source restoration/epoch change, inode replacement or backup tampering stay unavailable/HOLD; no automatic repair/adoption occurs.

## Supported writers and inventory

Persistent BEFORE INSERT/UPDATE/DELETE triggers fence `memories`, `memory_events` and `docs`, including access/expiry updates. They initially require `bosun_writer_floor_v1`, upgraded to a version-2 function by explicit publication, then advance generation transactionally per trigger execution. Generation is conservative and monotonic, not an exact committed-row counter: a docs UPSERT can execute both BEFORE INSERT and UPDATE. Existing plain/old already-prepared DML fails; a pre-cutover WAL read snapshot cannot upgrade to a stale writer after cutover.

`CutoverWriter` owns a new registered connection and admits only synchronous `transaction` callbacks under its own actual `BEGIN IMMEDIATE`. Its required function accepts mutations only while that wrapper's admission flag and native transaction are both active. It independently FULL-commits `HOLD` to the fixed gate before primary DML. A gate lease that prevents this commit prevents the primary mutation; primary rollback never undoes external HOLD. Cached handles/prepared statements cannot use the floor function after the callback. The authorizer denies transaction/savepoint manipulation, DDL, attach/detach and other PRAGMAs; the exact read-only `data_version` PRAGMA remains necessary for existing FTS maintenance. A failed rollback closes/poisons the writer instead of advertising admission as released on a reusable connection. Cleanup failures return finite errors and retry native close.

MemoryService and Docs accept a narrow internal synchronous session, not another domain port. Actual SQL bodies run inside admission even though public memory methods use asynchronous timing/Promise APIs. Constructor/lazy expiry, search touch, store/update/delete/accept/reject, purge/prune and docs insert/update/delete all use this path. Best-effort touch retains its existing busy-read behavior; a failed touch cannot partially mutate the primary or bypass HOLD. Registered reads revalidate the epoch/gate/floor/backup, and callback returns reject promises/direct native DB/statement handles. Plain `.db` compatibility remains only for plain stores; registered `.db` is unavailable. After successful rollback, authoritative MemoryError not-found/invalid/conflict/class/current-version semantics survive; unexpected native/proxy errors remain finite. Existing model projections/errors still hide private records and unverified version details.

## Qualification and limits

The guarded `cutover` suite exercises actual native WAL backup, logical parity/private audit preservation, destination format/mode/sidecars, old/prepared/read-snapshot fencing, wrapper/FTS behavior, primary/gate contention, four SIGKILL boundaries, restart without backup overwrite/doubleapply, late identity/epoch tampering, malformed input and cleanup/rollback failures. The `writer` suite exercises production-primitive-prepared synthetic roots through actual local APIs/owner CLI/stdio MCP/HTTP server/docs, constructor/lazy expiry/touch/pruning, domain/proxy errors, path overrides/pending/ambiguous gates and doctor CLI filesystem observations. Fixtures never open owner data. Use the mandatory Node launcher, isolated typecheck and AST boundary checker. `lib/memory/sqlite.ts → src/adapters/memory/sqlite-cutover.ts` is the exact recorded compatibility seam in ADR 0001; there is no production-to-test import or new port.

This is a trusted-application protocol. A same-user owner deliberately replacing UDFs/authorizers, dropping schema or directly altering FTS/shadow tables/files can bypass it. The callback must not replace connection controls, retain handles for unsupported operations, or perform asynchronous work. Ordinary memory/events/docs DML is fenced; arbitrary hostile SQLite access is not. Native SQL/backup and synchronous callbacks have no hard interruption deadline; size caps/zero busy wait bound admitted data and contention, not strict total latency. The optional checkpoint is explicit owner progress/testing and may prolong admission.

Process-kill tests do not qualify power-loss durability, native-host/Bun behavior or other platforms. Explicit owner activation still must check permissions/paths and drain or restart every old authority: existing cached/plain writers fail after floor/format commit and are never silently upgraded. [ADR 0006](0006-explicit-public-memory-publication.md) records implemented explicit publication and remaining capacity/reader binding/delivery-expiry/uncertainty gates. No floor apply command, default WAL fallback or owner schema is activated by this implementation.
