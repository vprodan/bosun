# 0012 · Context ranking and compatible composition

**Date:** 2026-10-06. **Status:** Implemented as a narrow context extraction; hook snapshots/lean closure and remaining v1.0 work are unfinished.

## Decision

`createRetrieveContext` in core owns actual retrieval orchestration, scoring, dedupe, greedy budget and rendering. The existing ContextSource port supplies an explicit verified identity, weight, half-life and search callback. Construction copies/freezes that metadata and the callbacks, preserving a method's receiver. Unsupported/unverified sources are skipped before search acquisition. Capability metadata comes from trusted composition; it is neither inferred from returned hits nor authentication of arbitrary hostile adapter objects. No Graphify/CodeGraph source is activated or installed.

Semantic time, monotonic time, content hash, UTC date label and numeric measurement are injected. The core imports only core and reads no ambient HOME/config/clock/sink, filesystem, native SQLite or network. Explicit source callbacks may own effects. Core never installs source indexing, maintenance, retries, fallback or lifecycle/close handling. AST boundaries reject ambient clocks, native/platform imports and obsolete legacy forwarding edges; direct-child fixtures exercise unusable ambient state.

`lib/context.ts` preserves `retrieve`, `curated`, Item/Result types and exact `estTokens` forward identity. The compatible source allowlist admits only curated, docs and claude-mem before acquiring their search callback, with fixed reviewed metadata regardless of supplied provider fields. Actual hook, MCP, authoritative serve and owner bench callers use this delegation. Curated classification remains before denied record metadata/body access. The unchanged hash definition moved to `src/platform/content-hash.ts`, with the exact function reexported from `lib/memory/sqlite.ts`: normalized title/newline/body, SHA-256, first 32 hex characters. This removes context's native writer dependency without changing stored IDs/hashes or dedupe.

## Compatibility

The query remains at most 24 deterministic task terms from the first 20,000 characters. Each admitted source is asked for 20 hits. Relevance is normalized by that source's best negative BM25 rank. Weights remain 1/0.8/0.6; half-lives remain 60/90/30 days, with curated sessions at one day. Scores retain the 0.3 recency and 0.05 logarithmic usage terms. Stable score ties preserve source/hit order. Same hashes or word-set Jaccard at least 0.8 dedupe after ranking; the first/highest result wins.

Matched counts gate before payload access, capped by actual task terms; omitted counts remain ungated. Unknown/mismatched hit source identity is rejected before title/text/matched access. Scored/output hits contain only explicitly projected declared fields, with optional hash/matched presence preserved; arbitrary provider extras/getters and serialization hooks never enter output. Source counts retain returned-list length, including rejected identities. Open verified core IDs use own count properties, including prototype-like names; the legacy allowlist does not admit them.

One-line rendering, whitespace normalization, item truncation, 60 reserved header characters, greedy smaller-item fitting, source/category/UTC day/ID/title/snippet and character-divided-by-four estimates remain compatible. Finite fractional docs mtime and negative Date-range hit timestamps remain valid; the legacy ten-character ISO day projection is retained, including its extended-year truncation. Empty terms invoke no sources and retain the unmeasured fast path. Provider-domain errors propagate unchanged. No HTTP/MCP/schema/storage/query-policy or selected-model change is introduced.

## Held malformed inputs and measurement

The following explicit checks replace previously incidental NaN/type/getter failures:

- Trusted scope IDs are null or nonempty strings of at most 200 characters without NUL; linked scope contains at most 2000 such strings. Optional source is a valid string. Scope and linked entries are copied/frozen before callbacks.
- Budget is finite nonnegative and at most the safe-integer maximum. Minimum score is finite. Item characters are a positive safe integer; minimum matched terms are a nonnegative safe integer. Invalid options/scope/task fail before source invocation with a fixed invalid error.
- Verified source ID follows the same finite string rule. Weight is finite nonnegative and at most the safe-integer maximum; half-life is finite positive and at most that maximum. Composition admits at most 64 verified callbacks. Invalid metadata/dependency functions fail with a fixed invalid error; invalid metadata is rejected before search acquisition.
- Source responses must be arrays of at most 1000 hits, checked before hit access. Rank must be finite; access count is finite nonnegative and at most the safe-integer maximum. Hit time is finite within the signed Date range; optional matched count is a nonnegative safe integer, and optional hash is a string. Declared ID/title/text/category are strings. Malformed admitted fields or throwing getters hold the complete result with a fixed unavailable error, without returning partial content.
- The semantic clock must be finite nonnegative Date milliseconds. Clock, hash or date-label failures hold output with a fixed unavailable error. The injected hash must return a string and date label must match the compatible UTC day shape. These checks do not authenticate adapter metadata or impose provider payload byte bounds.

Timing is best effort. Failed, nonfinite, negative, backward or otherwise invalid monotonic samples yield zero duration. A failed initial sample cannot create a misleading large elapsed value from a later success. Sink failures never change a completed result; timing/sink failures also cannot replace an original provider-domain error. Only the fixed `context.retrieve` operation and finite duration/item/character/token numbers reach measurement, with no titles, IDs, prompts, source payloads or errors. Like the prior implementation, failed/empty-term retrievals emit no retrieval measurement.

## Qualification and remaining work

Guarded Node fixtures characterize genuine ranking/rendering/providers, privacy and actual hook/MCP/HTTP behavior before extraction. New `contextpipeline` acceptance covers exact forwards/hash behavior, deterministic dependencies and scores, fractional/extended dates, stable ties, all dedupe arms, greedy token edges, 50 KB prompts, disabled/mismatched source getter canaries, explicit projections, metadata/callback/scope snapshots, finite malformed fields/counts, semantic/timing/sink failures and actual denied curated delegation. `contracts` includes these tests; `context` selects the existing context/provider/hook tests and retains legacy-suite coverage. Existing native writer/reader, public READY/HOLD, retained stdout lease/cancellation and real caller suites verify compatible delegation. Counts and independent verification belong in the implementation ledger.

The local reader's native lease still survives through stdout acceptance; finite-expiry notes stay excluded, and HOLD/revocation/cancellation remain intact. This extraction adds no general model delivery or finite-expiry eligibility claim. Legacy metrics/config, MemoryService expiry/touch and compatible docs indexing still perform effects outside core. Hook JSON/config snapshots and whole lean closure, daemon query/index/maintenance migration, central COMMIT storage capacity, artifact disposition/drain and every remaining native/Clef/handoff/graph/UI/remote/ship gate remain required in the same single v1.0.
