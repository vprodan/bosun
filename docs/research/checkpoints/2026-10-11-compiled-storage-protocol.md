Bun1.4.2 implements the native node:sqlite DatabaseSync API, including defensive/extension configuration, named parameter binding, UDFs, authorizer callbacks and backup. Its [tagged native implementation](https://github.com/oven-sh/bun/blob/bun-v1.4.2/src/jsc/bindings/sqlite/NodeSqlite.cpp) and [upstream API tests](https://github.com/oven-sh/bun/blob/bun-v1.4.2/test/js/node/sqlite/node-sqlite.test.ts) establish implementation candidates, not passing local qualification. The [publisher compatibility reference](https://bun.com/docs/runtime/nodejs-compat) says macOS uses system libsqlite3.dylib and backup blocks the JS loop synchronously. The actual loaded version must be queried from the connection; the bundled version cannot stand in for it. No custom library/install is selected by this work.

Source preparation pins the compiled runtime candidate to Bun1.4.2 on macOS arm64. Native Node24+ POSIX behavior is preserved. Owner/cutover runtime admission uses that shared platform predicate while retaining actual SQLite-version branches3.44.6+,3.50.7+,3.51.3+,3.52+ and required backup/UDF/authorizer APIs. Unsupported versions, platform/architecture drift and missing APIs remain held. This is candidate admission, not a native safety/locking/retention claim. The Node application test launcher still rejects Bun before imports.

Public hook delivery stays held. The [tagged stdout implementation](https://github.com/oven-sh/bun/blob/bun-v1.4.2/src/js/builtins/ProcessObjectInternals.ts) selects an internal FileSink fast path for process.stdout. Its [stream implementation](https://github.com/oven-sh/bun/blob/bun-v1.4.2/src/js/internal/fs/streams.ts) can call write callbacks after FileSink.write without a separate flush acknowledgement. Consequently the existing Node callback/retained-SQLite-lease contract must not be copied onto Bun by removing its guard. An explicit ordinary fs.WriteStream/custom fs.write path could avoid that buffer, but failure/termination semantics and independent original-process lease evidence still require qualification. No unsupported native field or new transport/SDK/executor was added.

Bun's [tagged SQLite termination code](https://github.com/oven-sh/bun/blob/bun-v1.4.2/src/jsc/bindings/sqlite/JSSQLStatement.cpp) closes SQLite handles during VM teardown. Retaining a JavaScript reader reference alone does not prove its native lease survives every pending native write until OS producer teardown. Keep the existing guard until the original process/pipe/lease path is established.
